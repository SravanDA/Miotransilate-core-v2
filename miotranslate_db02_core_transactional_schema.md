The `admin` schema is defined first because most other tables reference `admin.users` and `admin.languages` as FKs. Creation order matters.

### 2.1 `admin.users`

**Classification:** `SOURCE_OF_TRUTH`  
**FRD Reference:** §2, §5.7, §8  
**Entity Model:** ED-01 §User  
**ED-03 Contract:** §2.11

**Purpose:** Canonical identity record for every MioTranslate user. Created on first authenticated access. Never deleted.

```sql
CREATE TABLE admin.users (
    -- Identity
    user_id             UUID            NOT NULL,
    display_name        VARCHAR(255)    NOT NULL,
    email               VARCHAR(320)    NOT NULL,
    external_auth_id    VARCHAR(512)    NULL,           -- Opaque ID from external auth provider

    -- Account state
    is_active           BOOLEAN         NOT NULL DEFAULT TRUE,

    -- Timestamps
    created_at          TIMESTAMPTZ     NOT NULL DEFAULT now(),
    updated_at          TIMESTAMPTZ     NOT NULL DEFAULT now(),

    -- Constraints
    CONSTRAINT users_pkey PRIMARY KEY (user_id),
    CONSTRAINT users_email_unique UNIQUE (email)
);

COMMENT ON TABLE admin.users IS
    'SOURCE_OF_TRUTH: Authoritative identity record for every MioTranslate user. '
    'Created on first authenticated access. Never deleted (is_active = FALSE for deprovisioned accounts).';

COMMENT ON COLUMN admin.users.user_id IS
    'UUID v7 (time-ordered). Generated by the application at first authentication. '
    'Globally unique. Immutable after creation.';
COMMENT ON COLUMN admin.users.external_auth_id IS
    'Opaque identifier from the external authentication provider (e.g., SSO, OAuth). '
    'NULL if auth is handled internally. Used to match inbound auth tokens to user records.';
COMMENT ON COLUMN admin.users.is_active IS
    'FALSE for deprovisioned accounts. Deprovisioned users retain all their authored records '
    '(Audit Records, English Copy Versions, Translation Versions). Not a deletion.';
```

**Triggers:**
```sql
CREATE TRIGGER users_set_updated_at
    BEFORE UPDATE ON admin.users
    FOR EACH ROW EXECUTE FUNCTION public.set_updated_at();

CREATE TRIGGER users_no_delete
    BEFORE DELETE ON admin.users
    FOR EACH ROW EXECUTE FUNCTION public.raise_on_delete();
```

**Indexes:**
```sql
-- users_email_unique constraint creates an implicit unique index on (email).
-- No additional indexes required. Table is small (< 50 rows), PKs and unique email suffice.
```

**Enforcement Notes:**
- **DB-enforced:** `user_id` uniqueness (PK), `email` uniqueness (UNIQUE).
- **Application-enforced:** UUID v7 generation at first auth; `display_name` and `email` populated from auth provider claims.
- **No FK on `created_by` referencing users from users** — chicken-and-egg on the first user; that user is bootstrapped outside normal API flows.

```sql
CREATE TABLE admin.languages (
```

### 2.3 `admin.user_role_assignments`

**Classification:** `GOVERNANCE_RECORD` + `IMMUTABLE_HISTORY` (grant records are permanent; revocation is append-once)  
**FRD Reference:** §5.7, §8  
**Entity Model:** ED-01 §UserRoleAssignment  
**ED-03 Contract:** §2.12

**Purpose:** Point-in-time history of every role grant and revocation. Active roles are those where `revoked_at IS NULL`. A user may hold multiple roles simultaneously (one active row per role).

```sql
CREATE TABLE admin.user_role_assignments (
    -- Identity: surrogate UUID v7 (grant records accumulate over time)
    assignment_id       UUID            NOT NULL,

    -- Assignment target
    user_id             UUID            NOT NULL REFERENCES admin.users(user_id),

    -- Role
    role                VARCHAR(10)     NOT NULL,

    -- Grant
    assigned_by         UUID            NOT NULL REFERENCES admin.users(user_id),
    assigned_at         TIMESTAMPTZ     NOT NULL DEFAULT now(),

    -- Revocation (append-once — written at most once, never changed after set)
    revoked_at          TIMESTAMPTZ     NULL,
    revoked_by          UUID            NULL     REFERENCES admin.users(user_id),

    -- Timestamps
    created_at          TIMESTAMPTZ     NOT NULL DEFAULT now(),

    -- Constraints
    CONSTRAINT user_role_assignments_pkey PRIMARY KEY (assignment_id),
    CONSTRAINT user_role_assignments_role_check
        CHECK (role IN ('PM', 'QA', 'LR', 'SR', 'FN', 'DEV', 'ADMIN')),
    CONSTRAINT user_role_assignments_revoke_consistency
        CHECK (
            (revoked_at IS NULL AND revoked_by IS NULL) OR
            (revoked_at IS NOT NULL AND revoked_by IS NOT NULL)
        )
);

COMMENT ON TABLE admin.user_role_assignments IS
    'GOVERNANCE_RECORD + IMMUTABLE_HISTORY: Every role grant and revocation is a permanent record. '
    'Active roles: WHERE revoked_at IS NULL. A user may have multiple active roles simultaneously.';

COMMENT ON COLUMN admin.user_role_assignments.revoked_at IS
    'NULL = role is currently active. Set once when role is revoked. Never cleared after being set.';
COMMENT ON COLUMN admin.user_role_assignments.assignment_id IS
    'UUID v7 (time-ordered). Grants accumulate over time so a surrogate key is required.';
```

**Partial Unique Index — Active Role Deduplication:**
```sql
-- At most one active grant per (user_id, role).
-- Revoked grants are excluded — historical revocations for the same role are permitted.
-- Enforces: a user cannot be granted the same role twice concurrently.
CREATE UNIQUE INDEX user_role_assignments_active_unique
    ON admin.user_role_assignments (user_id, role)
    WHERE revoked_at IS NULL;
```

**Triggers:**
```sql
-- Grant records may have revoked_at/revoked_by written once (the append-once fields).
-- The immutability trigger allows this narrow update: only revoked_at and revoked_by may change,
-- and only when transitioning from NULL to a non-NULL value.
CREATE TRIGGER user_role_assignments_immutability
    BEFORE UPDATE ON admin.user_role_assignments
    FOR EACH ROW EXECUTE FUNCTION admin.validate_role_assignment_update();

CREATE TRIGGER user_role_assignments_no_delete
    BEFORE DELETE ON admin.user_role_assignments
    FOR EACH ROW EXECUTE FUNCTION public.raise_on_delete();
```

```sql
-- Trigger function: only allow setting revoked_at/revoked_by from NULL
CREATE OR REPLACE FUNCTION admin.validate_role_assignment_update()
RETURNS TRIGGER AS $$
BEGIN
    -- assignment_id, user_id, role, assigned_by, assigned_at, created_at are immutable
    IF NEW.assignment_id  <> OLD.assignment_id  OR
       NEW.user_id        <> OLD.user_id        OR
       NEW.role           <> OLD.role           OR
       NEW.assigned_by    <> OLD.assigned_by    OR
       NEW.assigned_at    <> OLD.assigned_at    THEN
        RAISE EXCEPTION 'Immutable fields on user_role_assignments cannot be changed';
    END IF;
    -- revoked_at and revoked_by: once set, cannot be changed
    IF OLD.revoked_at IS NOT NULL AND NEW.revoked_at <> OLD.revoked_at THEN
        RAISE EXCEPTION 'revoked_at is append-once: cannot be changed after being set';
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

**Indexes:**
```sql
-- Active roles for a specific user (RBAC check on every API request)
CREATE INDEX idx_user_role_assignments_user_active
    ON admin.user_role_assignments (user_id)
    WHERE revoked_at IS NULL;

-- All users with a specific active role (e.g., find all LRs to notify)
CREATE INDEX idx_user_role_assignments_role_active
    ON admin.user_role_assignments (role)
    WHERE revoked_at IS NULL;

-- Full assignment history for a user (API-0801)
CREATE INDEX idx_user_role_assignments_user_id
    ON admin.user_role_assignments (user_id, assigned_at DESC);
```

**Enforcement Notes:**
- **DB-enforced:** Active role uniqueness per user (partial unique index). Revoke consistency (`CHECK`). Role value validity (`CHECK`). Immutable field protection (trigger).
- **Application-enforced:** Admin-lockout guard — must verify that at least one `ADMIN` or `FN` role assignment remains active before permitting a revocation. This is a count-based rule that PostgreSQL cannot enforce without a trigger.

### 2.4 `admin.system_configuration`

**Classification:** `SOURCE_OF_TRUTH` (singleton — key-value store)  
**FRD Reference:** §5.7, F-09  
**Entity Model:** ED-01 §SystemConfiguration  
**ED-03 Contract:** §2.18

**Purpose:** Stores system-wide configuration parameters. Key-value design allows individual settings to be queried and updated atomically. Each key has its own `etag_version` for optimistic concurrency.

**Canonical Configuration Keys (seed data):**

| Key | Default Value | Type | Purpose |
|---|---|---|---|
| `bulk_approval_confidence_threshold` | `0.95` | DECIMAL | Minimum confidence score for bulk approval |
| `par_expiry_duration_hours` | `24` | INTEGER | Publishing Approval Request TTL in hours |
| `env_endpoint_dev` | TBD | URL | DEV environment Language Services endpoint |
| `env_endpoint_qa` | TBD | URL | QA environment Language Services endpoint |
| `env_endpoint_production` | TBD | URL | PRODUCTION environment Language Services endpoint |
| `language_services_domain` | `miosalon` | STRING | Domain value sent in bulkImportPages payloads |
| `recently_edited_retention_days` | `30` | INTEGER | Retention limit for search.recently_edited_events |
| `export_ttl_hours` | `24` | INTEGER | Export file TTL before expiry |

```sql
CREATE TABLE admin.system_configuration (
    -- Identity: natural key (configuration setting name)
    config_key          VARCHAR(100)    NOT NULL,

    -- Value
    config_value        TEXT            NOT NULL,
    value_type          VARCHAR(20)     NOT NULL DEFAULT 'STRING',

    -- Documentation
    description         TEXT            NULL,

    -- Actor (who last updated this setting)
    updated_by          UUID            NOT NULL REFERENCES admin.users(user_id),

    -- Concurrency (per-key ETag — settings are updated independently)
    etag_version        INTEGER         NOT NULL DEFAULT 1,

    -- Timestamps
    created_at          TIMESTAMPTZ     NOT NULL DEFAULT now(),
    updated_at          TIMESTAMPTZ     NOT NULL DEFAULT now(),

    -- Constraints
    CONSTRAINT system_configuration_pkey PRIMARY KEY (config_key),
    CONSTRAINT system_configuration_value_type_check
        CHECK (value_type IN ('STRING', 'INTEGER', 'DECIMAL', 'BOOLEAN', 'URL', 'JSON'))
);

COMMENT ON TABLE admin.system_configuration IS
    'SOURCE_OF_TRUTH: System-wide configuration parameters. Key-value design. '
    'Each key has independent etag_version for optimistic concurrency. '
    'Seed data must be inserted on first deployment.';

COMMENT ON COLUMN admin.system_configuration.config_key IS
    'Canonical configuration key name. Immutable (cannot be renamed). '
    'Deleting a config key is prohibited — mark as deprecated in description instead.';
COMMENT ON COLUMN admin.system_configuration.etag_version IS
    'Incremented on every UPDATE. Used with If-Match for concurrent configuration edits. '
    'Protects against concurrent administrator updates to the same setting.';
```

**Triggers:**
```sql
CREATE TRIGGER system_configuration_set_updated_at
    BEFORE UPDATE ON admin.system_configuration
    FOR EACH ROW EXECUTE FUNCTION public.set_updated_at();

CREATE TRIGGER system_configuration_etag_increment
    BEFORE UPDATE ON admin.system_configuration
    FOR EACH ROW EXECUTE FUNCTION public.increment_etag();

-- No delete trigger: configuration keys are permanent (see description above)
CREATE TRIGGER system_configuration_no_delete
    BEFORE DELETE ON admin.system_configuration
    FOR EACH ROW EXECUTE FUNCTION public.raise_on_delete();
```

**Indexes:**
```sql
-- PK covers all single-key lookups. No additional indexes required.
-- All configuration keys fit in a single sequential scan (< 20 rows).
```

### 3.1 `registry.pages`

**Classification:** `SOURCE_OF_TRUTH`  
**FRD Reference:** §5.1, F-01, F-02  
**Entity Model:** ED-01 §Page  
**ED-03 Contract:** §2.1  
**DB-01 Reference:** §4.2 (natural primary key)

**Purpose:** Canonical registry of every MioSalon page registered in MioTranslate. The root of the entire content hierarchy. All other entities trace back to a page.

```sql
CREATE TABLE registry.pages (
    -- Identity: natural primary key (developer-assigned, externally meaningful)
    page_id             VARCHAR(100)    NOT NULL,

    -- Attributes
    page_name           VARCHAR(255)    NOT NULL,
    module              VARCHAR(100)    NULL,           -- Optional MioTranslate-internal grouping (PD-3)

    -- Lifecycle
    status              VARCHAR(20)     NOT NULL DEFAULT 'ACTIVE',

    -- Actor
    created_by          UUID            NOT NULL REFERENCES admin.users(user_id),

    -- Concurrency
    etag_version        INTEGER         NOT NULL DEFAULT 1,

    -- Timestamps
    created_at          TIMESTAMPTZ     NOT NULL DEFAULT now(),
    updated_at          TIMESTAMPTZ     NOT NULL DEFAULT now(),

    -- Constraints
    CONSTRAINT pages_pkey PRIMARY KEY (page_id),
    CONSTRAINT pages_status_check
        CHECK (status IN ('ACTIVE', 'DEPRECATED'))
);

COMMENT ON TABLE registry.pages IS
    'SOURCE_OF_TRUTH: Canonical registry of every MioSalon page in MioTranslate. '
    'Root of the content hierarchy. Never deleted — deprecated via status transition.';

COMMENT ON COLUMN registry.pages.page_id IS
    'Developer-assigned page identifier (e.g., QUICK, CUSWISH, INVOICE). '
    'Immutable after creation. Must be unique across all pages (active and deprecated). '
    'Sent as pageId in Language Services bulkImportPages payloads.';
COMMENT ON COLUMN registry.pages.page_name IS
    'Human-readable page name. Mutable via API-0106. '
    'Sent as pageName in Language Services payloads.';
COMMENT ON COLUMN registry.pages.module IS
    'Optional MioTranslate-internal grouping (e.g., POS, CRM, Calendar). '
    'Not present in Language Services. Mutable via API-0106. NULL until explicitly set.';
COMMENT ON COLUMN registry.pages.status IS
    'ACTIVE: page is in use. DEPRECATED: all tags deprecated; page excluded from active workflows. '
    'Deprecation is a cascade from API-0107 (last tag deprecated). '
    'Direct deprecation via API is not supported (application must check all-tags-deprecated condition).';
COMMENT ON COLUMN registry.pages.etag_version IS
    'Incremented on every UPDATE (page_name, module, status changes). '
    'Protects against concurrent metadata updates.';
```

**Triggers:**
```sql
CREATE TRIGGER pages_set_updated_at
    BEFORE UPDATE ON registry.pages
    FOR EACH ROW EXECUTE FUNCTION public.set_updated_at();

CREATE TRIGGER pages_etag_increment
    BEFORE UPDATE ON registry.pages
    FOR EACH ROW EXECUTE FUNCTION public.increment_etag();

CREATE TRIGGER pages_no_delete
    BEFORE DELETE ON registry.pages
    FOR EACH ROW EXECUTE FUNCTION public.raise_on_delete();
```

**Indexes:**
```sql
-- Active pages list (API-0103 — most common query)
CREATE INDEX idx_pages_status_active
    ON registry.pages (page_id)
    WHERE status = 'ACTIVE';

-- Filter by module (API-0103 with module filter parameter)
CREATE INDEX idx_pages_module
    ON registry.pages (module)
    WHERE module IS NOT NULL;

-- Note: All-pages scan (89 rows) is trivially fast even without a status index.
-- The above partial indexes are for correctness of intent, not query performance.
```

**Transaction Participation:**
- **Tag deprecation → Page cascade (§12.3):** When the last active tag on a page is deprecated (API-0107), the page itself is deprecated in the same transaction: `UPDATE registry.pages SET status = 'DEPRECATED', etag_version = etag_version + 1 WHERE page_id = $1 AND status = 'ACTIVE'`.

### 3.2 `registry.tags`

**Classification:** `SOURCE_OF_TRUTH`  
**FRD Reference:** §5.1, F-02  
**Entity Model:** ED-01 §Tag  
**ED-03 Contract:** §2.2  
**DB-01 Reference:** §4.2 (natural PK), DB-R-01 (prefix constraint), DB-R-02 (search vector)

**Purpose:** Canonical registry of every UX copy tag. The fundamental unit of content. Every English copy, translation, comment, and deployment snapshot traces back to a tag.

```sql
CREATE TABLE registry.tags (
    -- Identity: natural primary key (developer-assigned, globally unique)
    tag_id              VARCHAR(150)    NOT NULL,

    -- Parent
    page_id             VARCHAR(100)    NOT NULL REFERENCES registry.pages(page_id),

    -- Attributes (mutable via API-0108)
    copy_type           VARCHAR(100)    NULL,           -- Optional MioTranslate-internal classification (PD-4)

    -- Lifecycle
    status              VARCHAR(20)     NOT NULL DEFAULT 'ACTIVE',

    -- Full-text search vector (DB-R-02)
    -- Covers tag_id for searchability via API-0701
    search_vector       TSVECTOR        GENERATED ALWAYS AS (
                            to_tsvector('simple', tag_id)
                        ) STORED,

    -- Actor
    created_by          UUID            NOT NULL REFERENCES admin.users(user_id),

    -- Concurrency
    etag_version        INTEGER         NOT NULL DEFAULT 1,

    -- Timestamps
    created_at          TIMESTAMPTZ     NOT NULL DEFAULT now(),
    updated_at          TIMESTAMPTZ     NOT NULL DEFAULT now(),

    -- Constraints
    CONSTRAINT tags_pkey PRIMARY KEY (tag_id),
    CONSTRAINT tags_page_id_fkey
        FOREIGN KEY (page_id) REFERENCES registry.pages(page_id),
    CONSTRAINT tags_status_check
        CHECK (status IN ('ACTIVE', 'DEPRECATED')),
    CONSTRAINT tags_tag_id_prefix_check
        CHECK (tag_id LIKE replace(page_id, '%', '\%') || '\_%' ESCAPE '\')
        -- Enforces: tag_id must begin with page_id followed by underscore.
        -- e.g., page_id=QUICK → tag_id must start with QUICK_
);

COMMENT ON TABLE registry.tags IS
    'SOURCE_OF_TRUTH: Canonical registry of every UX copy tag. '
    'The fundamental unit of content. Creation triggers creation of: '
    '(1) one english_copies record in NO_COPY state; '
    '(2) one translations record per active language in NO_TRANSLATION state. '
    'Both are application-enforced side-effects of API-0102.';

COMMENT ON COLUMN registry.tags.tag_id IS
    'Developer-assigned tag identifier (e.g., QUICK_1, CUSWISH_FEMALE). '
    'Immutable after creation. Must begin with page_id followed by underscore. '
    'Sent as tagName in Language Services bulkImportPages payloads — tag_id IS the Language Services tag name.';
COMMENT ON COLUMN registry.tags.copy_type IS
    'Optional MioTranslate-internal classification (e.g., BUTTON_LABEL, ERROR_MESSAGE). '
    'Not present in Language Services. Mutable via API-0108. NULL until explicitly set.';
COMMENT ON COLUMN registry.tags.status IS
    'ACTIVE: tag participates in translation, review, and publishing workflows. '
    'DEPRECATED: excluded from all active workflows. History and content retained. '
    'Deprecated via API-0107.';
COMMENT ON COLUMN registry.tags.search_vector IS
    'Generated tsvector for full-text search via API-0701. '
    'Uses ''simple'' dictionary (no stemming) to preserve tag_id identifiers exactly. '
    'Automatically updated when tag_id changes — but tag_id is immutable, so this is static.';
```

**Triggers:**
```sql
CREATE TRIGGER tags_set_updated_at
    BEFORE UPDATE ON registry.tags
    FOR EACH ROW EXECUTE FUNCTION public.set_updated_at();

CREATE TRIGGER tags_etag_increment
    BEFORE UPDATE ON registry.tags
    FOR EACH ROW EXECUTE FUNCTION public.increment_etag();

CREATE TRIGGER tags_no_delete
    BEFORE DELETE ON registry.tags
    FOR EACH ROW EXECUTE FUNCTION public.raise_on_delete();
```

**Indexes:**
```sql
-- Tags within a page (API-0104 — get all tags on a page)
CREATE INDEX idx_tags_page_id
    ON registry.tags (page_id, tag_id);

-- Active tags within a page (most common query — publishing, coverage denominator, slot creation)
CREATE INDEX idx_tags_page_id_active
    ON registry.tags (page_id)
    WHERE status = 'ACTIVE';

-- All active tags system-wide (API-0506 — new language slot creation iterates all active tags)
CREATE INDEX idx_tags_active
    ON registry.tags (tag_id)
    WHERE status = 'ACTIVE';

-- Full-text search (API-0701 — global search by tag_id)
CREATE INDEX idx_tags_search_vector
    ON registry.tags USING GIN (search_vector);
```

**Tag ID Prefix Constraint — Detail:**  

The `CHECK` constraint `tag_id LIKE replace(page_id, '%', '\%') || '\_%' ESCAPE '\'` enforces that every `tag_id` begins with `page_id_`. For example:
- `page_id = 'QUICK'` → `tag_id` must match `QUICK\_%` → `QUICK_1`, `QUICK_SALE` are valid; `INVOICE_1` is not.
- `page_id = 'CUSWISH'` → `tag_id` must match `CUSWISH\_%`.

The `replace(page_id, '%', '\%')` escapes any `%` characters in `page_id` values (defensive, as page IDs are alphanumeric in practice).

**Side-Effects on Tag Creation (Application-enforced):**

API-0102 must, in a single transaction:
1. INSERT into `registry.tags`
2. INSERT into `content.english_copies` (`tag_id`, `status = 'NO_COPY'`)
3. For each `language_code` WHERE `admin.languages.status = 'ACTIVE'`: INSERT into `translation.translations` (`tag_id`, `language_code`, `status = 'NO_TRANSLATION'`)
4. INSERT into `system_ops.audit_records` per the audit contract

All four steps are in one `SERIALIZABLE` transaction.

## 4. English Copy Domain (`content` schema)

**Classification:** `SOURCE_OF_TRUTH` (live operational state)  
**FRD Reference:** §5.2, F-04, F-05  
**Entity Model:** ED-01 §EnglishCopy  
**ED-03 Contract:** §2.3  
**DB-01 Reference:** OQ-1 (no denormalization onto tags), OQ-2 (live-state table)

**Purpose:** The live operational state of the English copy for each tag. One row per tag, always. Created simultaneously with the tag. Tracks current status and version pointer. Joins to `english_copy_versions` for content.

```sql
-- Immutability enforcement: only narrow, documented mutations are permitted
CREATE OR REPLACE FUNCTION content.validate_ecv_update()
RETURNS TRIGGER AS $$
BEGIN
    -- Content snapshot fields: absolutely immutable
    IF NEW.text          <> OLD.text          OR
       NEW.authored_by   <> OLD.authored_by   OR
       NEW.authored_at   <> OLD.authored_at   THEN
        RAISE EXCEPTION 'Immutable content snapshot fields on english_copy_versions cannot be changed';
    END IF;

    -- Status: only APPROVED → SUPERSEDED is permitted as a post-creation change
    -- DRAFT → PENDING_REVIEW → APPROVED are handled by INSERT of new rows? No:
    -- The status column lives on the version row. Status transitions ARE updates.
    -- Permitted transitions:
    --   DRAFT        → PENDING_REVIEW (API-0202 submit)
    --   PENDING_REVIEW → APPROVED      (API-0203 approve)
    --   PENDING_REVIEW → DRAFT         (API-0203 return for revision)
    --   PENDING_REVIEW → REJECTED      (API-0203 reject)
    --   APPROVED      → SUPERSEDED    (when new version approved)
    -- All other status transitions are application errors.
    IF NEW.status <> OLD.status THEN
        IF NOT (
            (OLD.status = 'DRAFT'           AND NEW.status = 'PENDING_REVIEW') OR
            (OLD.status = 'PENDING_REVIEW'  AND NEW.status IN ('APPROVED', 'DRAFT', 'REJECTED')) OR
            (OLD.status = 'APPROVED'        AND NEW.status = 'SUPERSEDED')
        ) THEN
            RAISE EXCEPTION 'Invalid status transition on english_copy_versions: % → %',
                OLD.status, NEW.status;
        END IF;
    END IF;

    -- Append-once fields: once set, cannot be cleared or overwritten
    IF OLD.approved_at IS NOT NULL AND NEW.approved_at <> OLD.approved_at THEN
        RAISE EXCEPTION 'approved_at is append-once and cannot be changed after being set';
    END IF;
    IF OLD.reviewed_at IS NOT NULL AND NEW.reviewed_at <> OLD.reviewed_at THEN
        RAISE EXCEPTION 'reviewed_at is append-once and cannot be changed after being set';
    END IF;

    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

```sql
BEGIN
    -- Immutable snapshot fields
    IF NEW.text                     <> OLD.text                     OR
       NEW.creation_method          <> OLD.creation_method          OR
       NEW.source_english_version   <> OLD.source_english_version   OR
       NEW.authored_at              <> OLD.authored_at              THEN
        RAISE EXCEPTION 'Immutable content snapshot fields on translation_versions cannot be changed';
    END IF;

    -- Status transition validation
    IF NEW.status <> OLD.status THEN
        IF NOT (
            (OLD.status = 'DRAFT'           AND NEW.status = 'PENDING_REVIEW') OR
            (OLD.status = 'PENDING_REVIEW'  AND NEW.status IN ('APPROVED', 'DRAFT', 'REJECTED')) OR
            (OLD.status = 'APPROVED'        AND NEW.status = 'SUPERSEDED')
        ) THEN
            RAISE EXCEPTION 'Invalid status transition on translation_versions: % → %',
                OLD.status, NEW.status;
        END IF;
    END IF;

    -- Append-once fields
    IF OLD.approved_at IS NOT NULL AND NEW.approved_at <> OLD.approved_at THEN
        RAISE EXCEPTION 'approved_at is append-once on translation_versions';
    END IF;
    IF OLD.reviewed_at IS NOT NULL AND NEW.reviewed_at <> OLD.reviewed_at THEN
        RAISE EXCEPTION 'reviewed_at is append-once on translation_versions';
    END IF;

    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

```sql
CREATE OR REPLACE FUNCTION publishing.validate_release_update()
RETURNS TRIGGER AS $$
BEGIN
    -- Core identity and classification fields: immutable
    IF NEW.release_id       <> OLD.release_id       OR
       NEW.page_id          <> OLD.page_id          OR
       NEW.language_code    <> OLD.language_code    OR
       NEW.environment      <> OLD.environment      OR
       NEW.deployment_version <> OLD.deployment_version OR
       NEW.release_type     <> OLD.release_type     OR
       NEW.trigger_source   <> OLD.trigger_source   THEN
        RAISE EXCEPTION 'Immutable identity fields on releases cannot be changed';
    END IF;

    -- Status transitions allowed:
    IF NEW.status <> OLD.status THEN
        IF NOT (
            (OLD.status = 'PENDING'     AND NEW.status = 'IN_PROGRESS') OR
            (OLD.status = 'IN_PROGRESS' AND NEW.status IN ('SUCCESSFUL', 'FAILED')) OR
            (OLD.status = 'SUCCESSFUL'  AND NEW.status = 'ROLLED_BACK')
            -- FAILED releases cannot be retried into a new state; a new Release is created instead.
        ) THEN
            RAISE EXCEPTION 'Invalid status transition on releases: % → %', OLD.status, NEW.status;
        END IF;
    END IF;

    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

```sql
    subject_entity_id       TEXT            NULL,

    -- Content
    title                   VARCHAR(500)    NOT NULL,
    body                    TEXT            NULL,

    -- Delivery state
    delivery_status         VARCHAR(20)     NOT NULL DEFAULT 'PENDING',
    delivered_at            TIMESTAMPTZ     NULL,
    delivery_error          TEXT            NULL,   -- Error detail on FAILED delivery

    -- User read state (append-once)
    status                  VARCHAR(20)     NOT NULL DEFAULT 'UNREAD',
    read_at                 TIMESTAMPTZ     NULL,

    -- Timestamps
    created_at              TIMESTAMPTZ     NOT NULL DEFAULT now(),
    updated_at              TIMESTAMPTZ     NOT NULL DEFAULT now(),

    -- Constraints
    CONSTRAINT notifications_pkey PRIMARY KEY (notification_id),
    CONSTRAINT notifications_status_check
        CHECK (status IN ('UNREAD', 'READ')),
    CONSTRAINT notifications_delivery_status_check
        CHECK (delivery_status IN ('PENDING', 'DELIVERED', 'FAILED')),
    CONSTRAINT notifications_read_consistency
        CHECK (
            (status = 'UNREAD' AND read_at IS NULL) OR
            (status = 'READ'   AND read_at IS NOT NULL)
        ),
    CONSTRAINT notifications_delivery_consistency
        CHECK (
            (delivery_status = 'DELIVERED' AND delivered_at IS NOT NULL) OR
            (delivery_status <> 'DELIVERED' AND delivered_at IS NULL) OR
            (delivery_status = 'PENDING')  -- delivered_at may be NULL while pending
        )
);

COMMENT ON TABLE system_ops.notifications IS
    'GOVERNANCE_RECORD + SYSTEM_EVENT: Per-user notification records. '
    'Created by API-0504 ASYNC after primary operation commits. '
    'Notification failure does not roll back the triggering operation. '
    'read_at is append-once (written once when user reads). '
    'Notifications are permanent records (not deleted).';

COMMENT ON COLUMN system_ops.notifications.delivery_status IS
    'PENDING: dispatch not yet attempted. DELIVERED: successfully delivered to recipient channel. '
    'FAILED: delivery failed (error captured in delivery_error). '
    'A FAILED delivery record is still a valid, readable notification (API-0906 returns it).';
COMMENT ON COLUMN system_ops.notifications.event_type IS
    'One of the 11 FRD §12 event types, e.g., NEW_TAG_CREATED, ENGLISH_COPY_APPROVED, '
    'TRANSLATION_STALE_FLAGGED, PAGE_BUNDLE_PUBLISHED_TO_PRODUCTION, ROLLBACK_INITIATED, etc.';
```

**Triggers:**
```sql
CREATE TRIGGER notifications_set_updated_at
    BEFORE UPDATE ON system_ops.notifications
    FOR EACH ROW EXECUTE FUNCTION public.set_updated_at();

-- Partial immutability: content fields are immutable; only status/read_at/delivery fields change
CREATE TRIGGER notifications_immutability
    BEFORE UPDATE ON system_ops.notifications
    FOR EACH ROW EXECUTE FUNCTION system_ops.validate_notification_update();

-- Notifications are permanent — no hard delete
CREATE TRIGGER notifications_no_delete
    BEFORE DELETE ON system_ops.notifications
    FOR EACH ROW EXECUTE FUNCTION public.raise_on_delete();
```

```sql
CREATE OR REPLACE FUNCTION system_ops.validate_notification_update()
RETURNS TRIGGER AS $$
BEGIN
    -- Immutable fields
    IF NEW.notification_id      <> OLD.notification_id      OR
       NEW.recipient_user_id    <> OLD.recipient_user_id    OR
       NEW.event_type           <> OLD.event_type           OR
       NEW.title                <> OLD.title                THEN
        RAISE EXCEPTION 'Immutable fields on notifications cannot be changed';
    END IF;
    -- read_at: append-once
    IF OLD.read_at IS NOT NULL AND NEW.read_at <> OLD.read_at THEN
        RAISE EXCEPTION 'read_at is append-once on notifications';
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

**Indexes:**
```sql

    ON system_ops.notifications (recipient_user_id, created_at DESC)
    WHERE status = 'UNREAD';

-- All notifications for a user (API-0906 with read/unread filter)
CREATE INDEX idx_notifications_user_all
    ON system_ops.notifications (recipient_user_id, created_at DESC);

-- Pending delivery (background delivery worker retry)
CREATE INDEX idx_notifications_delivery_pending
    ON system_ops.notifications (created_at)
    WHERE delivery_status = 'PENDING';
```

## 10. Shared Infrastructure Functions and Triggers

These functions must be installed in the `public` schema before any table triggers are created. They are referenced by name across all schema-specific triggers.

```sql
-- ============================================================
-- Function: public.set_updated_at()
-- Purpose:  Automatically update updated_at on every UPDATE.
-- Applied:  BEFORE UPDATE trigger on all mutable entity tables.
-- ============================================================
CREATE OR REPLACE FUNCTION public.set_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = now();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- ============================================================
-- Function: public.increment_etag()
-- Purpose:  Atomically increment etag_version on every UPDATE.
-- Applied:  BEFORE UPDATE trigger on tables with optimistic concurrency.
-- ============================================================
CREATE OR REPLACE FUNCTION public.increment_etag()
RETURNS TRIGGER AS $$
BEGIN
    NEW.etag_version = OLD.etag_version + 1;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- ============================================================
-- Function: public.raise_on_delete()
-- Purpose:  Prevent hard deletion of permanent business records.
-- Applied:  BEFORE DELETE trigger on all permanent tables.
-- ============================================================
CREATE OR REPLACE FUNCTION public.raise_on_delete()
RETURNS TRIGGER AS $$
BEGIN
    RAISE EXCEPTION
        'Hard deletion is prohibited on permanent table "%.%". '
        'Use status transitions (DEPRECATED, INACTIVE, CANCELLED) instead.',
        TG_TABLE_SCHEMA, TG_TABLE_NAME;
END;
$$ LANGUAGE plpgsql;

-- ============================================================
-- Function: public.raise_on_update()
-- Purpose:  Prevent any UPDATE on absolutely immutable tables.
-- Applied:  BEFORE UPDATE trigger on release_content_snapshots
--           and other fully-immutable tables.
-- ============================================================
CREATE OR REPLACE FUNCTION public.raise_on_update()
RETURNS TRIGGER AS $$
BEGIN
    RAISE EXCEPTION
        'Update is prohibited on immutable table "%.%".',
        TG_TABLE_SCHEMA, TG_TABLE_NAME;
END;
$$ LANGUAGE plpgsql;
```

## 11. Constraint Responsibility Matrix

This matrix classifies how each important product invariant is enforced. "DB-enforced" means PostgreSQL prevents the violation without application co-operation. "Application-enforced" means the invariant requires correct application code. "System-process-enforced" means a background process maintains the invariant.

| Invariant | Enforcement Level | Mechanism |
|---|---|---|
| `page_id` globally unique | **DB** | `PRIMARY KEY (page_id)` |
| `tag_id` globally unique | **DB** | `PRIMARY KEY (tag_id)` |
| `tag_id` must start with `page_id_` | **DB** | `CHECK (tag_id LIKE page_id || '\_%' ESCAPE '\')` |
| Tag must belong to exactly one Page | **DB** | `NOT NULL FK (page_id → pages.page_id)` |
| `(tag_id, language_code)` unique per Translation | **DB** | `PRIMARY KEY (tag_id, language_code)` |
| `(tag_id, version_number)` unique per EC Version | **DB** | `PRIMARY KEY (tag_id, version_number)` |
| `(tag_id, language_code, version_number)` unique per TV | **DB** | `PRIMARY KEY (tag_id, language_code, version_number)` |

## 12. Transaction Boundary Analysis

The following multi-table mutations must execute within a single database transaction with `SERIALIZABLE` isolation level (per DB-01 §12.2).

### 12.1 Tag Creation (API-0102)

**Participating tables:** `registry.tags`, `content.english_copies`, `translation.translations` (one per active language), `system_ops.audit_records`

```
Transaction (SERIALIZABLE):
  1. INSERT INTO registry.tags (tag_id, page_id, ...)
  2. INSERT INTO content.english_copies (tag_id, status='NO_COPY')
  3. SELECT language_code FROM admin.languages WHERE status='ACTIVE'
  4. INSERT INTO translation.translations (tag_id, language_code, status='NO_TRANSLATION')
     -- repeat for each active language (batch INSERT)
  5. INSERT INTO system_ops.audit_records (action='TAG_CREATED', subject=tag_id, ...)
  COMMIT
```

**Note:** Step 3's SELECT is within the SERIALIZABLE transaction, so no new languages can be added between the SELECT and the INSERTs. Language isolation is guaranteed.

### 12.2 English Copy Approval (API-0203 APPROVE action)

**Participating tables:** `content.english_copy_versions` (×2: PENDING_REVIEW → APPROVED, prior APPROVED → SUPERSEDED), `content.english_copies` (status update, current_version_number update), `translation.translations` (all languages for this tag → STALE + staleInfo), `system_ops.audit_records`

```
Transaction (SERIALIZABLE):
  1. SELECT FOR UPDATE on content.english_copies WHERE tag_id=$1 AND etag_version=$expected
     → 409 if mismatch
  2. SELECT FOR UPDATE on content.english_copy_versions WHERE tag_id=$1 AND status='APPROVED'
     → get prior approved version
  3. UPDATE content.english_copy_versions SET status='SUPERSEDED' WHERE tag_id=$1 AND status='APPROVED'
  4. UPDATE content.english_copy_versions SET status='APPROVED', approved_by=$user, approved_at=now()
     WHERE tag_id=$1 AND version_number=$current_version_number
  5. UPDATE content.english_copies SET status='APPROVED', current_version_number=$new_version
     WHERE tag_id=$1
  6. (Only if text changed from prior version):
     UPDATE translation.translations SET
       status='STALE',
       stale_triggered_at=now(),
       stale_triggered_by_english_ver=$new_ec_version,
       stale_prior_confirmed_ec_ver=$prior_ec_version,
       stale_current_english_text=$new_text,
       stale_previous_english_text=$prior_text,
       etag_version=etag_version+1
     WHERE tag_id=$1 AND status NOT IN ('NO_TRANSLATION', 'STALE')
  7. INSERT INTO system_ops.audit_records (action='ENGLISH_COPY_APPROVED', ...)
  COMMIT

Post-commit (async, outside transaction):
  → Dispatch notifications (API-0504)
  → Trigger implicit DEV publish check (API-0502) if conditions met
```

### 12.3 Translation Approval → Implicit DEV Publish (API-0304 APPROVE + API-0502)

**Step A — Translation Approval (SERIALIZABLE):**
```
  1. SELECT FOR UPDATE on translation.translations WHERE (tag_id, language_code) AND etag_version=$expected
  2. UPDATE translation.translations SET status='APPROVED' WHERE ...
     (No new TV created for direct APPROVE — ED-02 §7.2)
  3. INSERT INTO system_ops.audit_records (action='TRANSLATION_APPROVED', ...)
  COMMIT
```

**Step B — Implicit DEV Publish (separate transaction, SERIALIZABLE):**
```
  1. Evaluate publish conditions (within application, reading DB):
     - English Copy status = APPROVED? 
     - Language ACTIVE?
     - Page ACTIVE?
     - Any APPROVED translations exist for (page, language)?
     - No current in-flight Release for (page, language, DEV)?
     - Bundle hash different from last SUCCESSFUL DEV release?
  2. If all pass:
     a. SELECT MAX(deployment_version) FROM publishing.releases 
        WHERE page_id=$page AND language_code=$lang AND environment='DEV'
        FOR UPDATE
     b. INSERT INTO publishing.releases (... deployment_version = max+1, status='PENDING',
        trigger_source='SYSTEM_AUTO_DEV', published_by=NULL,
        published_by_source='SYSTEM:AUTO_PUBLISH')
     c. INSERT INTO system_ops.audit_records (action='PAGE_BUNDLE_AUTO_PUBLISHED_INITIATED', ...)
  COMMIT

Post-commit (async): Execute Language Services call → Update release status + insert content snapshots
```

**External call (OUTSIDE any transaction):**
```
  → POST /multilingual/bulkImportPages to DEV endpoint
  On success:
    BEGIN (separate transaction):
      INSERT INTO publishing.release_content_snapshots (one row per tag)
      UPDATE publishing.releases SET status='SUCCESSFUL', completed_at=now(), api_response_payload=...
      INSERT INTO system_ops.audit_records (action='PAGE_BUNDLE_AUTO_PUBLISHED_SUCCESS', ...)
    COMMIT
```

### 12.4 PAR Approval → Release Creation (API-0404 APPROVE)

```
Transaction (SERIALIZABLE):
  1. SELECT FOR UPDATE on publishing.publishing_approval_requests
     WHERE approval_request_id=$1 AND etag_version=$expected AND status='PENDING'
  2. Recompute bundle hash; compare with par.bundle_snapshot_hash
     → if mismatch: UPDATE par SET status='CANCELLED'; COMMIT → return 409
  3. UPDATE par SET status='APPROVED', decided_by=$user, decided_at=now()
  4. SELECT MAX(deployment_version) FOR UPDATE scope
  5. INSERT INTO publishing.releases (deployment_version=max+1, approval_request_id=$par_id,
     status='PENDING', trigger_source='USER_INITIATED', ...)
  6. INSERT INTO system_ops.audit_records (action='PUBLISHING_APPROVAL_GRANTED', ...)
  COMMIT

Post-commit (async): Execute publishing (same pattern as §12.3)
```

### 12.5 Tag Deprecation → Page Cascade (API-0107)

```
Transaction (SERIALIZABLE):
  1. SELECT FOR UPDATE on registry.tags WHERE tag_id=$1
  2. UPDATE registry.tags SET status='DEPRECATED' WHERE tag_id=$1
  3. SELECT COUNT(*) FROM registry.tags WHERE page_id=$page AND status='ACTIVE'
     → if 0 active tags remain:
       UPDATE registry.pages SET status='DEPRECATED' WHERE page_id=$page
  4. INSERT INTO system_ops.audit_records (action='TAG_DEPRECATED', ...)
  5. (if page deprecated): INSERT INTO system_ops.audit_records (action='PAGE_DEPRECATED', ...)
  COMMIT
```

### 12.6 Migration Import — Per-Page Batch (API-1002)

```
For each page in the import file:
  Transaction (SERIALIZABLE, per-page):
    1. INSERT INTO registry.pages (page_id, page_name, status='ACTIVE', ...)
    2. For each tag on this page:
       a. INSERT INTO registry.tags (tag_id, page_id, ...)
       b. INSERT INTO content.english_copies (tag_id, status='APPROVED', current_version_number=1)
       c. INSERT INTO content.english_copy_versions (tag_id, version_number=1, text=$en_text,
          status='APPROVED', authored_by=migration_system_user, ...)
       d. For each language with translation data:
          INSERT INTO translation.translations (tag_id, language_code,
            status='APPROVED', current_version_number=1)
          INSERT INTO translation.translation_versions (tag_id, language_code, version_number=1,
            text=$translated_text, creation_method='MIGRATED',
            source_english_version=1, ...)
          [source_ec FK is DEFERRED — satisfied within this transaction since ECv1 was just inserted]
    3. INSERT INTO publishing.releases (page_id, language_code, environment='PRODUCTION',
       deployment_version=1, status='SUCCESSFUL', trigger_source='MIGRATION', ...)
    4. INSERT INTO publishing.release_content_snapshots (one row per tag per language)
    5. INSERT INTO system_ops.audit_records (action='MIGRATION_PAGE_IMPORTED', ...)
  COMMIT
```

### 14.4 Remaining Open Items Identified in DB-02

| # | Item | Notes |
|---|---|---|
| DB-02-OI-01 | `system_ops.audit_records` table | Deferred to DB-06 per scope boundary. All transaction boundary analyses above include audit record INSERTs — the table definition must be available before DB-02 transactions can execute in production. Consider DB-06 a hard prerequisite for production deployment. |
| DB-02-OI-02 | `migration.import_events` table | Deferred to DB-09. Migration transactions (§12.6) write to import_events; the table must exist. DB-09 prerequisite for migration flow. |
| DB-02-OI-03 | `reporting.coverage_metrics` table | Deferred to DB-06. Coverage recalculation (API-0503) triggered by many events in this schema, but the coverage_metrics table itself is defined in DB-06. |
| DB-02-OI-04 | `published_by_source` values | Column exists on `releases`; no CHECK constraint defined (values are free-form strings like `SYSTEM:AUTO_PUBLISH`). Recommend adding CHECK if values are enumerable: `CHECK (published_by_source IN ('USER', 'SYSTEM:AUTO_PUBLISH', 'SYSTEM:MIGRATION'))`. To be confirmed before DB-02 is marked final. |
| DB-02-OI-05 | Search vector on `english_copy_versions.text` | The `search_vector` GENERATED column covers the `text` field for full-text search. However, API-0701 searches "approved and fallback" text. Currently the FTS covers all version texts. Restricting search to approved versions only may be preferable — this would require a function-based GIN index with a WHERE clause rather than a generated column. To be resolved in DB-07 (search schema). |
